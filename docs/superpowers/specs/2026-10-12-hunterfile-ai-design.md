# HunterFile：语义整理与本地生成

用户已授权继续第二步、第三步，并将项目和产品统一命名为 HunterFile。沿用已确认的本地处理、预览后应用和可撤销原则，不重复开启审批流程。

## 名称与兼容

应用、SwiftPM 项目与模块、浏览器扩展、文档、CLI 和内置插件使用 HunterFile。GitHub 仓库最后改名并验证新地址。旧资源库、素材包、采集令牌与插件桥继续兼容；原有库文件不改名或搬移。新版偏好从对应旧应用域迁移，QA 与正式版分开。测试版使用独立库，不停止正式应用。

## 第二步

语义智能文件夹保存自然语言描述、最低相似度和现有筛选规则；成员随可见的已索引素材动态更新，原件不复制。相似度门槛不是概率，可以编辑。旧关键词智能文件夹继续按原规则工作。关闭 AI、缺失模型或未建索引时显示明确状态，不把语义文件夹扩大为整个库。查询仍尊重规则组、类型、标签、锁定和回收站。

已有分类预览支持逐项选择，再批量应用；仅追加审核的标签和文件夹，支持撤销和重做。

## 第三步

固定修订的 Google Gemma 4 E2B LiteRT-LM 模型先在当前 M5 Pro / 24 GiB 实测文字、视觉和取消行为，再选默认后端。复用现有原生 C 运行库，不引入 Python 服务。模型不提交 Git；校验 SHA-256，设置页提供下载链接、选择和释放模型。

本地生成名称与摘要复用整理面板。名称默认不覆盖，用户显式选择后应用；摘要保存为独立 AI 字段，保留人工备注。每项建议附原素材指纹；素材被编辑、删除或锁定后拒绝应用过期建议。原文件不重命名，所有元数据修改支持撤销与重做。

素材问答先在当前范围检索，再用可见素材片段和匹配图片、PDF 页、视频画面回答，显示可打开的来源。资料不包含指令权限，不启用模型工具调用；引用只接受提供的来源，内容不足时说明。上下文与画面数量有上限，文档摘要或视频摘要明确可能基于片段、采样画面；不新增音轨转录。

## 验收和实施顺序

1. 统一名称，验证构建入口与旧格式、偏好、插件兼容。
2. 验证语义文件夹持久化、门槛、所有/任一规则、增量变化、模型缺失和锁定过滤；批量预览、应用和撤销。
3. 用真实生成模型验证图片/PDF 名称与摘要、带来源问答和取消；无模型普通测试覆盖响应校验、指纹防冲突、摘要保留备注、撤销。
4. 运行完整测试、生成独立 HunterFileQA，实际检查三个新增用户流程及签名。最后保存提交与 GitHub 改名。

改动只达到上述入口、调用者、配置、测试与文档，不重构无关功能。大图库速度和个人素材准确率不由受控样本推算。
